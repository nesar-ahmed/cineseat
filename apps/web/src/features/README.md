# features

Feature code, one folder per domain (guideline section 5.2). Design rationale and the
catalog data contract are in [`../../DESIGN.md`](../../DESIGN.md).

| Folder | Contents |
| --- | --- |
| `catalog/` | Shared by home and the movies page: TanStack Query hooks over the catalog, movie, show and theater endpoints (`queries.ts`), poster art direction (`art.ts`), formatting in the cinema's time zone (`format.ts`), generated key art (`poster-art.tsx`), the poster card (`movie-card.tsx`) and movie links (`links.ts`). |
| `landing/` | Home page sections: hero billboard, quick booking, now showing / coming soon rails, offers, seat tiers with the sample hall, cinemas, FAQ, account CTA. `content.ts` holds what has no API of its own (offers, seat tiers, FAQ, certificate labels) and states only what the site does; `seat-map.tsx` is the sample hall (pick, reserve, hold — nothing booked). |
| `movies/` | The catalog page: URL query model and its mapping to API parameters (`catalog-query.ts`), the URL-synced state hook, filter panel and showtime buttons. The movie page (`app/movies/[id]`): `movie-details.tsx` (hero, cast & crew, details, more like this, booking bar; day/city/show mirrored in the URL), `movie-showtimes.tsx` (city switch, day strip, times per cinema) and `movie-not-found.tsx`. |
| `auth/` | Phase 1 session UI: `auth-provider.tsx` (context: who is signed in, login/signup/logout) and `auth-forms.tsx` (login + signup forms, validated with the shared Zod schemas). |
| `account/` | The user panel; every URL is in `links.ts`, every page starts with `panel-header.tsx` (breadcrumb, eyebrow, title, actions), and every list uses `list-controls.tsx` (filter pills with counts, numbered pages — both links, so the state is in the URL). `/account` is the overview (`account-overview.tsx`): greeting, live counts and profile completeness, a banner while seats are held for payment, tiles to every panel page (`account-shortcuts.tsx`), recent bookings (`recent-bookings.tsx`) and the settings card with sign-out. `settings/` is `/account/settings/*` (the bare path redirects to profile in `proxy.ts`): `settings-shell.tsx` (section nav — side list on desktop, pills on phones), `form-kit.tsx` (panel, field, password input, unsaved-changes warning, focus on the first error), `profile-settings.tsx`, `email-settings.tsx` and `password-settings.tsx`. Old `/account?tab=…` links are redirected to these pages in `proxy.ts`. `admin-users` and `notice` are kept from the old panel. |
| `seats/` | The seat page (`app/shows/[id]/seats`): live seat map and seat holds. `queries.ts` (seat map refreshed every 10 s, the buyer's current hold, reserve/release), `seat-grid.tsx` (the hall by priced section; one tab stop, arrow keys between seats), `hold-summary.tsx` (side panel and mobile bar with the hold countdown), `seat-picker.tsx` (picks, sign-in round trip via `?seats=`, seats taken meanwhile, hold expiry). |

| `checkout/` | The checkout page (`app/checkout/[id]`), also where the payment gateway returns the buyer (`?payment=`): order summary with the hold's clock, offer codes (quote API), start paying (then off to the gateway), "Confirming your payment…" while the webhook arrives, and the not-completed / hold-ended states. Once paid it hands over to the ticket page. |
| `bookings/` | Reading bookings (`queries.ts`: one booking, a page of them by status, counts) and what a booking means now (`ticket-state.ts`: Today, Upcoming, Screened, Awaiting payment, Hold ended, Refunded, Not completed, Cancelled — with its label, colour and next step; the list, the ticket page and the overview all use it). `my-tickets.tsx` is `/account/bookings`: status filters with counts and numbered pages, both in the URL (`?status=&page=`), drawn as `ticket-card.tsx` stubs. `booking-details.tsx` is `/account/bookings/:id`: the ticket as a pass (`booking-ticket.tsx`, notched at the perforation; struck through and marked not valid until paid), a status timeline, the receipt by seat category with a link to its invoice (when `hasInvoice(booking)`, the shared rule), the venue with directions, calendar file and copy-code. Checkout sends the buyer here after paying (`?confirmed=1` adds "You're booked!"). |
| `invoices/` | Invoices from the invoices API (`queries.ts`: a page by status, counts, one invoice). `invoices-list.tsx` is `/account/invoices`: Paid / Refunded filters and numbered pages in the URL, a table on wide screens (whole row opens) and cards on phones. `invoice-page.tsx` is `/account/invoices/:id` (the booking's id): `invoice-document.tsx` draws the invoice as a light sheet that prints as-is — site header, footer and page actions carry `print:hidden`, and `globals.css` keeps the sheet's colours on paper. `format.ts` writes money the invoice way (`BDT 1,600.00`, from the currency the API states) and dates on the cinemas' clock. |
| `notifications/` | In-app notifications for both panels. `queries.ts`: TanStack Query hooks on a **scope** — `USER_SCOPE` (bookings, offers, account) or `ADMIN_SCOPE` (admin) — for a page of an inbox view, a bell's preview, the unread badge (polled every 30 s and on focus) and counts per category and type, plus the changes (read/unread, mark all read, delete), optimistic across every cache with rollback; keys are scoped by user id. `notification-inbox.tsx`: the full inbox both panels use (filter pills with counts, cards grouped by day, pages in the URL, remove with undo — deleted on the server once the undo window closes); `notifications-page.tsx` is the user panel's (`/account/notifications`). `notification-bell.tsx`: the bell (site header for users; the admin top bar wraps it for admins). `kinds.ts`: each of the 19 types' tag, icon, colour and action — user types link into the user panel, admin types to their admin page (`features/admin/links.ts`). `notification-card.tsx`, `time.ts`. |
| `admin/` | The admin panel (`/admin/*`, ADMIN only; `app/admin/layout.tsx` reads the sidebar cookie on the server). `links.ts`: every admin URL (also used by notification links). `nav.ts`: the left navbar's sections, with the API each page will use — unbuilt pages show "Soon", are not linked, and mark where you are if a link lands in them. `admin-shell.tsx`: role check, fixed sidebar that minimizes to icons (cookie), drawer on small screens. `admin-sidebar.tsx` (tooltips when minimized), `admin-topbar.tsx`, `admin-bell.tsx` (the notification bell on the admin scope). `notifications/`: `/admin/notifications`, the shared inbox on the admin category (all, unread, sales, sign-ups, alerts). `coming-soon.tsx` + `app/admin/[...slug]`: links into sections not built yet land on "coming soon" inside the frame; other addresses get `app/admin/not-found.tsx`. `dashboard/`: `/admin` from GET /admin/dashboard. `toaster.tsx`: short confirmations with an optional Undo (`useToast`, provided by the shell). `use-url-query.ts`: list state kept in the URL (the catalog's approach, generic). `cache.ts`: `refreshAfterChange` — after any admin change, the admin views and the public caches (movies, catalog, cinemas, showtimes, seat maps) refresh together. `ui/`: the kit every admin module is built from — `list-kit.tsx` (tabs with counts, search with "/", filters button, sort control, filter chips, results footer with pages, empty / error / loading states, sortable header, checkbox, selection and paging hooks), `filter-kit.tsx` (the filter drawer with a draft, groups, toggle pills, segmented choice, date range), `form-kit.tsx` (sections, chip input, segmented and card choices, number stepper, `serverFieldErrors` mapping `field: message` answers onto fields), `page-kit.tsx` (page header, back link, figures, panels, facts, key/value rows, the history timeline, missing / failed / loading pages), `bulk-kit.tsx` (bulk bar, "will be skipped" notice, failures dialog), `hall-map.tsx` (a hall from the back, by seat category — layouts — or by state — a show's live map), `bits.tsx` (tag, badge, poster thumbnail, occupancy bar) and `format.ts` (dates and times on the cinemas' clock, `cinemaInstant`, taka ↔ poisha). `movies/`: the movies module — `list-query.ts` (the list's URL model and its GET /admin/movies parameters), `queries.ts`, `movies-page.tsx` (`/admin/movies`), `movies-table.tsx`, `filter-drawer.tsx`, `bulk-bar.tsx`, `movie-actions.tsx` (status switch with Undo, delete dialog), `movie-form.tsx` (`/new` and `/:id/edit`), `movie-detail.tsx` (`/:id`, with links to schedule the movie and to its showtimes), `poster-panel.tsx` and `bits.tsx`. `theaters/`: `/admin/theaters` (`theaters-page.tsx`: city tabs with counts, cards with screens, today, coming up, revenue and sold-ahead), `/admin/theaters/:id` (`theater-detail.tsx`: figures, screen cards with their layout drawn, next shows, history including screens), `theater-dialog.tsx` (add / edit a cinema), `screen-dialog.tsx` (add / edit a screen with a live layout preview; the layout locks once it has shows), `theater-actions.tsx` (delete dialogs that say why not), `list-query.ts`, `queries.ts`. `shows/`: `/admin/shows` (`shows-page.tsx`: a list — upcoming / today / past / all tabs, filters by day, theater, screen, city, movie, format, language, how full and sales, sort, bulk reprice or cancel — or a day board, `day-board.tsx`: one day screen by screen on a time axis, turnaround hatched, colour by how full), `/admin/shows/:id` (`show-detail.tsx`: live seat map, seats and prices per category, latest bookings, what can change, history), `/admin/shows/new` (`schedule-page.tsx`: a movie on a screen at every time of every chosen day, checked live with the API's dry run), `show-dialog.tsx` (change time, format, language, price), `show-actions.tsx` (cancel dialog), `shows-table.tsx`, `show-list.tsx` (short lists of shows, reused by theater pages), `bulk-bar.tsx`, `list-query.ts`, `queries.ts`, `bits.tsx`. `bookings/` (read-only): `/admin/bookings` (`bookings-page.tsx`: totals of the view, status tabs with counts, search by code / buyer / movie, filters by payment outcome, booked and show days, theater, movie and offer code, sortable table or cards) and `/admin/bookings/:id` (`booking-detail.tsx`: tickets, every payment attempt at `#payments`, money, the buyer and their history, a timeline, a countdown while a hold is being paid); `bits.tsx` says what a status means now (a PENDING booking past its hold reads "Hold ended"); `#payment-<id>` opens on one attempt, highlighted. `payments/` (read-only): `/admin/payments` (`payments-page.tsx`: the money in the view — collected, refunded, failed, open — outcome tabs with counts, search by reference, booking code or buyer, filters by channel, days and amount in taka, sortable table or cards; each row opens the attempt on its booking), `bits.tsx` (card / bKash / Nagad marks), `list-query.ts`, `queries.ts`. `users/`: `/admin/users` (`users-page.tsx`: role tabs with counts, search by name, email or phone, filters booked or never and joined days, sortable table or cards, a "⋯" per account with their bookings, payments and the role) and `/admin/users/:id` (`user-detail.tsx`: figures, latest bookings and payments, profile, what they book most, admin access with the reason it is locked, history of role changes), `role-dialog.tsx` (give or take away admin access, confirmed), `bits.tsx` (avatar, role badge), `list-query.ts`, `queries.ts`. The list kit's `TotalsStrip` / `TotalTile` are the strips on top of bookings and payments |
| `mock-gateway/` | CineSeat Test Pay (`app/pay/mock/[ref]`): the mock gateway's hosted payment page — its own light look, no CineSeat header or footer, TEST MODE banner, card / bKash / Nagad with one-tap test data. Real card numbers are refused by the API; nothing is charged. |
